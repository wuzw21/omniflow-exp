## 一、Action Transfer 算法的价值与证明

### Action Transfer 有什么用
- 解决：录制在设备 A 上的 action，在设备 B 上重放时，由于 layout/OEM/版本不同，元素位置和 XML attribute 都可能不同
- 机制：找 anchor 元素对 → 投影 source action → 投票选 target element
- 权重公式：`vote = Sim(e,e') · Sim(a,a*) · Dis(e,a)`（从局部到外扩展）

### Selector 会不会干掉 Action Transfer
- `selector 完好 → selector lookup 永远 >= action transfer`（逻辑上无法反驳）
- **核心前提**：resource-id 在真实移动端本来就不好，selector 天然不可用
- 因此比较应该是：action transfer vs selector lookup vs coordinate scaling（三路对比）
- Action transfer 的价值在 selector 失效的场景（第三方 app、跨设备、WebView）

### 怎么证明有用
- Ablation 三路对比：selector lookup / coordinate scaling / anchor transfer
- 在 MobileGPT dataset（80 pairs × 8 apps）上离线跑，不需要真实设备
- Gold label 直接来自 source_json / target_json 的 step alignment（免费标注）

## 二、我们的向量编码特性

- Element vector 包含 resource-id hints（作为特征之一）
- 因此：当 selector 完好时，element similarity 极高 → action transfer 也命中同一元素
- 结论：`我们永远 >= selector`（在 selector 完好的场景下也不会更差）
- 但需要注意边界：layout 变化极大时，anchor 投影可能排除正确候选

## 五、论文定位与投稿策略

### OmniFlow 的核心价值
> 人类演示一次 → 跨设备、跨用户、零模型调用重放

**系统工程价值 > 研究方法价值**

### 和 MobileGPT 的本质区别（一句话）
MobileGPT 用 LLM 分配 HTML element index 做 grounding，warm-start 时仍需要 LLM。
OmniFlow 用 feature vector + anchor transfer，cache hit 时零模型调用。
**一个改变（encoder）使得系统不依赖 LLM 做 grounding。**

### 投稿策略（三个月三篇）

**月1 → ICLR 2027（算法论文）**
- 主张：cross-device UI element transfer 在 XML attribute 缺失时比 selector/coordinate 更准确
- 需要：MobileGPT 80 pairs 离线跑 ablation
- Baseline：selector lookup / coordinate scaling / OmniParser（可选）
- 工程量：小，不需要设备

**月2 → MobiCom 2027（系统论文）**
- 主张：人类演示跨设备共享 Function，O(u) 成本
- 需要：4 台设备跨设备 replay + multi-round 摊销曲线
- 核心实验：在 Pixel 6 录制，在其他 3 台设备重放

**月3 → 视数据情况**

### 最高优先级实验
1. MobileGPT 80 pairs 离线 ablation（最急，决定 ICLR 可行性）
2. 4 台设备跨设备 replay（支撑 MobiCom）
3. Multi-round（不同 seed）摊销曲线（2-3 天完成）

## 六、核心 Insight（论文没有说清楚的）

### 真正的 insight

> **Structural features of UI elements, without semantic understanding, are sufficient for cross-device action transfer.**

Prior work（OmniParser/SeeClick/MobileGPT）假设需要语义理解才能 ground 元素。
OmniFlow 证明：结构+几何特征已足够，不需要理解"这个按钮是什么意思"。

### 为什么是 1-shot 问题
- 给定 1 个 source element demonstration
- 在新 screen 找对应元素
- 这是 **1-shot correspondence**，不是 grounding（text→element）

### 和 grounding 的区别
| | Grounding | Action Transfer |
|--|--|--|
| Input | 自然语言 | Source element |
| 需要语义理解 | 是 | 否 |
| 模型调用 | 每次 | 零次 |
| 问题类型 | text→element | element→element |

## 七、UI Encoder 与匹配的技术讨论

### 速度约束（手机 CPU）
- 每次 action 都要 encode 50-200 个元素 + 计算 pairwise similarity
- 必须 < 10ms，在手机 CPU（~10^9 float ops/sec）上

**计算量对比**：
- dot product（n×m=100×100）：640K ops → 0.6ms ✓
- MiniGlue（2层 attention）：~15M ops → 15ms ✗
- 结论：MiniGlue 在线不可用

### 正确的 encoder 方向
**速度约束下唯一可行**：手工特征的加权打分（selector-based）

```
sim(e_src, e_tgt) = 加权组合（
    text_hash 匹配,
    resource_id 匹配（条件性）,
    widget_type,
    interaction_flags,
    bounds_relative,
    subtree_hash
）
```

**当前问题**：
1. 线性加法，假设特征独立（应该是乘法关系）
2. 缺失特征被惩罚（缺少 resource-id 应该是信息缺失，不是负分）
3. 权重是手调的（应该从数据学）

### 可学习组件设计

**输入**：feature vector + presence mask（~60-dim × 2）
**交互层**：`concat([v_src ⊙ v_tgt, |v_src - v_tgt|, v_src ⊙ mask_tgt, v_tgt ⊙ mask_src])`
**网络**：MLP(240 → 32 → 8 → 1)，~8K 参数
**训练数据**：MobileGPT pairs，400 正样本 × 10 hard negatives = 4000 样本
**速度**：< 1ms for 200 elements（只用于最终 1×m scoring，不用于 n×m anchor）

**参考工作**：
- DeepMatcher（KDD 2018）：entity matching，问题完全同构
- LightGlue（ICCV 2023）：keypoint matching，架构参考

### LightGlue 适配
原版：9层 attention，13.7M 参数，~6.7ms @1024 keypoints（太重）
MiniGlue：2层，64-dim，~50K 参数，< 1ms @200 elements
输出：n×m assignment matrix + matchability score（处理 no-match 情况）

## 八、Few-shot 与 Cluster 质量

### Few-shot Merge
- 1-shot → 1 个 element vector
- Few-shot → k 个观测的均值（Prototypical Networks 思路）
- 跨设备录制 k 次 → prototype 更稳定，跨设备特征被保留，不稳定特征被平均

### Cluster 质量问题（重要）
**现象**：top-1 retrieval 准（98.63% Hit@1），但 cluster 质量差（容易误匹配）

**原因**：page vector 捕获视觉/结构相似性，但不是 action compatibility。
Gmail 未读收件箱 vs Gmail 促销标签页：page vector 相近，但可用 actions 完全不同。

**解法**：cluster 判断标准加一层：page similarity AND key action element transferability
```
同一 cluster 的条件：
  page_sim > threshold  AND
  对所有 key actions，transfer_success 都成立
```

### 核心统一视角
**Action transfer accuracy = 整个系统的基础**

```
transfer accuracy
    → cluster 质量（cluster 由 transfer 定义）
    → Function recall 准确率
    → end-to-end SR
```

Ablation 不是可选实验，而是整个系统可信度的基础。
