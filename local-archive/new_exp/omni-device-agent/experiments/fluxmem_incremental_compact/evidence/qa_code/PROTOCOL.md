# 固定采样后的三对照：先等价，再计成本

使用已固定 FluxMem commit 6fdbf65、官方 Qwen2.5-VL-3B BF16 权重及 StreamingBench sample_1 原视频。作者源码不改；重用原相邻匹配、Otsu、剪枝及长期聚类函数。short=8、medium=64，原 direct_drop_sim_threshold，不训练、不改变记忆选择策略。

采样：视频 PTS 0,1,...,81 秒，固定 1 FPS；[0,1]、[2,3]... 为不可变两帧块，前缀采用 [0,t)。未完整的两帧块不补帧、不提前处理；53 秒问题使用已完成的前 52 帧。逐块保存抽样 PTS 和哈希。三个条件都使用同一输入，视觉塔固定每次一个时间块，避免随前缀改变 batch shape。

A：每个检查点重新执行所有视觉块及作者完整记忆过程。
B：保存原始视觉特征，仅编码新块；每个检查点重新执行作者完整记忆过程。
C：保存原始视觉特征和记忆执行状态；仅对新块执行相邻匹配，以及实际越过短/中期边界的剪枝/合并。重用原 helper，不重写策略。

验证分两层：
- 连续前缀审计：2,4,...,82 秒，共 41 个检查点。逐点比较实际视觉输出、保留的原 token 位置、合并后特征。检查短期窗口 8 帧以及长期开始 74 帧的边界；同一状态重复读取不得改变内部 mask 或触发新运算。
- 原始三题 QA：4、53、82 秒。A 实际重新执行视觉/记忆；B 读已验证视觉缓存，运行原记忆；C 读已增量维护的记忆快照。比较真实压缩入口所有输出（特征、位置、RoPE、mask）、首 token logits 和完整生成 token，不只比较选项。所有语言 prefill/decode 都重新执行，不复用 KV。

41 点审计是等价性压力测试，不假定真实用户问了 41 次。另在原三题时间轴运行/记录三条件，实际核对运算次数，不能把审计频率带来的重复当作真实负载收益。

记录实际调用：视觉块数/patch token、相邻匹配、剪枝、长期合并，以及更新和读取耗时。逐点统计去重后的持久 tensor storage 字节与 Python 容器开销；测量快照/比较副本、权重、输入素材、临时工作区单独说明，不计作方法新增状态。初版 C 为验证保留完整原特征、合并特征、归一化特征和索引，不声称有界状态或最小内存。读取出的短期 keep mask 只能是副本，不能污染下次淘汰决策。

不删失败，不把近似相同写成 bitwise 相同。记录最大误差及保留位置差异；以作者全量路径作 oracle。如等价性不成立，先定位依赖或数值差异，不通过调阈值追平。视觉/记忆审计单独加载原视觉塔以降低设备压力；其时间不是完整模型常驻时的端到端性能。QA 另加载完整作者模型在真实 M4 执行。
