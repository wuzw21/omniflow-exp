# 端侧视觉编码门控：首轮入口实验

冻结于运行前。问题：同等证据保留要求下，对已保留画面的比较，是否比只比较最近画面更能减少实际视觉编码？本轮不实现新 Agent loop。

设备：本机 Apple M4、16 GiB，macOS 26.5.1。模型：已有 Qwen3-VL-2B-Instruct 原生视觉编码器，BF16/MPS。数据：Hcompany/trajectories 固定版本 ede2a362c99ddba0d03f439c47a0b8fea6abae22；按发布索引顺序，选择前 12 个不同任务名且 5–24 步的 AndroidWorld 轨迹，保留完整截图顺序。前六条为开发集，后六条为保留集；不按表现选择数据，不读取发布轨迹中的推理文本。

所有策略只见当前与过去截图，维护最多 4 张 FIFO 关键帧；不会保留被淘汰帧的视觉表示。筛选特征是 64×64 RGB 缩略图，距离为 [0,1] 像素平均绝对差。该廉价代理不是语义事件检测器，不代表 ActiveSight 或 SVMemAgent 的复现。

对照：全编码；固定间隔 2/3/4；仅比较最近已保留帧；比较四张已保留帧。后两者阈值同为 0.01/0.025/0.05/0.10/0.20。不使用事后 top-k、OCR、问题或全序列长度作筛选依据。首帧始终编码。

证据指标：离线 Apple Vision OCR 只用于构造参考，不送入筛选器。高置信度、至少 4 个字母数字、在整条轨迹只出现 1–2 帧、且之后至少还有一帧的文本行为短暂证据。询问时刻为最后出现帧的下一帧；若当时四张关键帧中仍有一张含此文本，计为保留。它是 OCR 参考证据召回代理，不是人工真值、问答正确率或任务成功率。同步记录每个失败案例。全编码对照用于核对指标。

开发集选择在证据召回 ≥95% 时编码比例最低的配置；如无配置满足则明确失败。阈值冻结后只评一次保留集。另保留完整阈值曲线，不能挑保留集最优点作为主结果。

若开发集没有合格配置，只运行预先指定的最保守变化阈值 0.01（或固定间隔 2）作失败成本诊断，不能称作通过质量门槛的方案。

实际运行所选策略与全编码对照的原生 Qwen 编码，含图片打开、筛选、官方预处理、MPS 编码及同步；不含 OCR 参考构造。三次重复，交错顺序。报告调用次数、端到端回放时间、编码时间、筛选时间、视觉 token 数和峰值 MPS 分配。不以调用次数折算能耗，不模拟模型运行时间。

判据：只有保留集召回下降不超过 2 个百分点，并且实际回放时间降低，才支持继续该配置。单轮不足以证明统计显著性。截图来自公开 AndroidWorld 记录；本机运行是真实 M4 算子测试，不是 Android 真机在线 Agent 验收，也不是连续视频/穿戴续航测试。
