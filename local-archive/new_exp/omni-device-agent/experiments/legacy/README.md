## 最新精确替换复核：有害修正保留，唯一联合额外收益对数值路径敏感

[精确 KV 替换与同进程复核](results/stage_a_splice_findings.md)：八题共 152 组层来源掩码；直接使用目标原生 KV 后，Jimmy Ellis→Joe Frazier 的有害修正仍存在。在该题，同样 16 层目标状态，替换低层仍错、替换高层恢复答案。整体结果尚不构成可部署的修复范围算法。

更重要的是，56 组中唯一与上一轮重算输出不同的精确替换，恰好使联合 oracle 的唯一额外 F1 收益消失。两题后验复核在同一进程、同一批状态上对每条路径重复三次，确认 Franc Roddam 的短答案/长句差异稳定出现，对约 1% 区间 KV 数值差异敏感。不能把这个格式收益当作稳健联合优势。全部真实 CUDA 作业已退出；当前不训练入口预测器，也未通过完整开发/评估、真实端云收益或创新门槛。

## 最新阶段 A：补齐固定目标的双因素对照，联合入口没有稳定额外收益

## 最新实际模型检查：仅导出公共文件的 KV 行仍可保留私有前文影响

[公共 KV 的依赖边界](results/public_kv_dependency_findings.md)：Qwen2.5-0.5B-Instruct 在本机 MPS 完成 64 次真实 forward。两份人工公共文档、八个单 token 私有标签；只读取最后一个公共 token 的某层 K/V（512 bytes），在已知源模型/模板的八候选匹配中得到 16/16 次唯一正确辨识。第一层没有这种区分能力；私有信息后置或完全不输入时，公共状态在所有标签间相同。入口 E 也从后续层起依赖私有前文。

这否定“删掉私有 token 对应的 KV 行即可按公共文件权限导出”的简单假设；不代表新攻击或一般隐私恢复能力。SafeKV/CachePrune 的客户端侧信道模型、Shadow 的明文 KV 模型与 GIFT 的信息流保护必须分开。九项回归完成；没有真实用户数据、云端调用或任务质量结果。框架仍需先比较公共前缀/私有后置与独立公共编码，不能直接把依赖跟踪包装成新贡献。

## 最新远程专家检查：更高命中率不代表更少往返，复杂放置未胜过简单对照

[远程专家依赖与放置消融](results/remote_expert_dependency_findings.md)：真实路由按完整段分离校准/评估（48,343 / 54,766 token），固定相同专家容量。16 GiB 全局频率放置有 56.99% 专家命中率，仍平均每 token 依赖 44.15 个远程层；优化整层完成率的候选 DP 降到 34.42，但简单装满整层已达 34.58，且 P95 更好（35 对 44）。该复杂候选没有足以继续投入的证据。14 项回归与 20 份放置交叉计数核验完成；这是 CPU 路由回放，不是实际模型/WAN 性能。

同轮核对 StateFlow 已有固定 KV owner、远程专家派发与聚合位置优化；Prism 已有频率驱动放置。不能将“状态不动、计算流动”或“热点专家放置”当作新贡献。给定固定放置，RTT=30 ms 时 34.42 个串行远程层本身约需 1.033 秒/token 的传播路径；这不是对所有放置的下界，也没有否定低 RTT、多序列吞吐或其他模型。当前停止在本模型上继续微调静态放置，保留完整小模型与稀疏云辅助的场景验证主线。

## 最新 MoE 筛选：允许流式换入后，WAN 权重字节下界仍很高

[流式专家换入下界](results/streaming_expert_findings.md)：对已有公开 103,109-token 路由，按非重叠窗口证明必须收到的字节至少为 `max(0, 使用过的专家载荷 − 全部本地权重存储)`，允许任意免费初始驻留、完美预取和换入换出。12/16 GiB 专家预算下，全轨迹平均至少为 81.81/50.56 MB/token，对应假设 1 Gbps 有效带宽下约 1.53/2.47 token/s 的摊销速度上界；不是实测网络或每步时延。

另完成前八段的固定次序 Belady/MIN 模拟和 16 项回归。这个结果补上此前完整窗口驻留分析不能覆盖流式加载的缺口，降低 WAN 专家仓库候选的优先级；若有未计费本地 SSD/CPU 副本，或云端直接执行专家，这个下界不适用。没有模型推理、真机 agent、新 GPU 作业或新机制结论。Hera 的同步联网假设及 EC² 文件名清单也已核对，但尚未找到可直接使用的断连/稀疏交接日志。

## 最新场景审计：离线数据源不是本地/云端模型交接

## 最新 CUDA 对照：三图编码约 25 ms，原样特征传输不占优

[真实 GPU 诊断与成本边界](results/mobile_vision_cuda_findings.md)：9207 RTX 4090 上，首次约 13 s 的三图编码来自 patch Conv3d 的 `SlowDilated3d` 回退。可写 kernel cache 无法解决；使用 PyTorch 官方卷积权重布局转换后选择 `Cudnn`，一/三图编码中位数为 10.61/24.82 ms。24 次 forward 完成，输入、权重与输出几何已核对。布局转换输出不逐位相同，另做 FP32 参考；两条 BF16 路径都有数值偏差，未验证 decoder 或任务质量，不能宣称无损交换。

三图完整特征 11.3 MB、原始 WebP 65.8 KB；假设 100 Mbps 时，特征序列化约 904 ms，原图序列化加编码约 30 ms，均非端到端 WAN 测量。当前降低原样特征传输的优先级，不能沿用 MPS 或异常慢 CUDA 算子为云端构造弱基线。所有本轮 GPU 作业已结束；状态与证据见 `results/mobile_vision_cuda_preparation.json`。

[EC²-Bench 合作审计](results/ec2_collaboration_audit.md) 也提示：独立云端顾问上下文可保留自己的追加前缀，独立前文不自动导致完整重算。四项上游原版 transcript 格式化测试完成，未运行该 benchmark。下一步须建立真实稀疏参与/断连场景，而非从状态异构直接推导系统收益。

## 最新算子实验：稀疏接管增加的不一定是语言 KV 重算

[稀疏接管算子分解](results/mobile_operator_findings.md)：在同一三图目标请求上，“此前只看到第一步”与“此前看到第三步”都只能复用 612-token 前缀，语言算子分别约 1.21/1.22 秒。区别主要在 encoder cache：需要编码三张/一张图，约 1.66/0.62 秒。计入理想驻留的 encoder 特征后，算子估计之和为 2.87/1.83 秒，不能继续沿用忽略 encoder cache 的弱基线。

24 次语言、12 次视觉算子计算完成；17 项相关回归通过。这是反事实目标调用的 MPS 单样本分解，没有实际端云 agent，算子时间相加不是端到端缓存服务。三张图的实际目标特征约 10.8 MiB，原始公开 WebP 约 64 KiB，进一步限制“端侧只做目标 encoder、上传特征”的适用网络。CUDA 对照现已完成，见上方最新记录；这里的 MPS 成本不能当作 CUDA 接收端成本。

## 最新真实 VLM 回放：裁剪减少输入，却增加重算

## 最新真实模型结果：紧凑通道的切分成立，问题变化未触发答案失效

## 已核实的文献边界

1. [Strata，OSDI 2026](https://www.usenix.org/system/files/osdi26-xie-zhiqiang.pdf)：分层 KV 存储、布局转换和 cache-aware 调度；论文明确主要针对单计算实例内存管理与调度。将 WAN 当成新增存储层，会额外引入容量字节数、RTT、低并发下缺少可重叠工作的问题。不同模型状态还不是相同缓存对象。
2. [EC2MoE](https://arxiv.org/html/2508.06024v1)：已经做端云专家路由、压缩与流水线。实验为 Switch Transformer、GLUE/SQuAD、256 token 输入、batch 4、top-1，模拟 300 Mbps 带宽及波动。不能把其结果直接外推为长上下文自回归 agent 的逐 token WAN 性能。
3. [SP-MoE](https://arxiv.org/abs/2510.10302)：draft-target 对应关系用于专家预取及计算/传输流水线；“让小模型预测大模型专家”不是未经探索的创意。
4. [Temporally Extended MoE](https://arxiv.org/html/2604.20156v1)：学习何时切换专家集合，已有持续驻留的模型机制。附录明确端到端系统与真实加载成本仍待实现。只提出固定一段时间的专家集合不能算新贡献。
5. [SpecEdge](https://papers.nips.cc/paper_files/paper/2025/file/8587069d00a69d0ea498d547fffad6dd-Paper-Conference.pdf)：边缘 draft、云端 verify、token 通信与重叠；有 WAN 实验。端云 speculative decoding 本身不是空白。
6. [WiSP](https://arxiv.org/html/2606.21868v1)：已研究低资源 MoE 的专家/KV 工作集竞争及动态分配，不能把统一管理两种状态当作全新贡献。
7. [EdgeWise](https://arxiv.org/html/2610.17560v1)：端侧主执行、选择性云端接管，并对传递完整历史/截断历史等做实验；支持研究真实交接，但不证明 KV 迁移值得做，也不证明端侧模型对任何该任务都必要。

## 已执行的边界计算

参数来自 [Qwen3-30B-A3B 配置](https://huggingface.co/Qwen/Qwen3-30B-A3B/raw/main/config.json)：48 层、hidden 2048、128 experts、top-8、4 KV heads、head dim 128。脚本嵌入已核实字段，使后续上游 main 变化不改变本次结果；这不是权重 revision 固定或实际权重实验。

假设单条自回归序列，逐层精确同步调用；每层远程专家可以合并请求，没有跨依赖层的完美预知、近似延迟执行或成功预取。

- 端侧只留每层原生 router，其余计算云端：每层需获得云端最新 hidden state 再返回路由。传播下界为 L×RTT，RTT=10/30/80ms 时为 0.48/1.44/3.84 秒/token，尚未计计算与序列化。
- 8K token、BF16、全层 GQA KV 为 768 MiB。在假设 20/100/1000 Mbps 单向带宽下，序列化时间分别为 322.12/64.42/6.44 秒。可重叠工作能改变可见等待，但不能消灭字节传输时间。
- 理想 4-bit 单 expert 为 2.25 MiB；每层驻留 8 个共 864 MiB，只计算三块 expert 矩阵，不含量化元数据、attention/router、KV 或额外专家。top-8 不代表后续整个任务只需要这 8 个。
- 合成反例：同为 8/384 个 expert miss，命中率同为 97.9167%；集中一层与分散八层的同步远程传播等待在 RTT=30ms 时分别是 30ms 与 240ms。
- IID 敏感性计算：单 expert 命中率 99% 时，48 层 top-8 每 token 期望 3.708 个阻塞层，仅传播约 111ms。实际路由高度相关，禁止用此假设冒充真实结果。

| 对独立上下文做 KV+入口 E 联合修正 | 可能降低跨模型接收共享材料的重算 | 来源 KV 可能含源私有前文；目标冷/热 cache 基线；oracle E 不能免费获得；网络字节可能盖过省下的计算 | 保留阶段 A 协议，只有质量空间和端云成本均成立再推进 |

## 当前更有辨识力的研究问题

暂不声称创新已确认。待验证的问题是：能否借 agent 阶段边界，把未来一小段执行所需的模型工作集提前放在端侧，使该段没有同步 WAN 依赖；云端只承担阶段更新与必要接管？

与一般预取的区别必须通过证据建立：优化对象应是整条依赖链上的阻塞次数、连续本地执行长度与阶段完成时间，而不只是专家字节命中率。仅改一个指标不是论文贡献。

这个问题也可能失败：

1. 全模型放在本地 SSD 就足够快，云端权重源没有优势。
2. agent 阶段不对应稳定/可预测的专家集合。
3. 即使有未来知识，所需集合也装不下或传不完。
4. 固定专家损失质量；换专家后旧 KV 不能无条件视作全模型原生 KV。
5. 本地只能运行很弱模型，而云端整轮执行显著更好，所谓合作反而更慢。

## 下一项实证与明确停止条件

先采集真实 MoE 路由，不做新推理框架。候选：Qwen3-30B-A3B（主模型）与可运行的小 MoE（代码管线校验，不代替主模型结果）。沿用维护中的上游模型实现，固定模型、tokenizer、运行时版本；只加路由日志钩子。

需要三类具有可验证输入的请求：一般文本/代码续写；长材料读取后结构化答复；包含真实工具返回的 agent 轨迹。首轮可 teacher-force 固定轨迹隔离路由，不得宣称是在线 agent 成功率。数据来源、许可证、任务边界和 test IDs 单独固定；不能使用本工作区私人对话作为默认实验数据。

对每段真实轨迹记录每 token 每层 top-k expert IDs、路由权重、prefill/decode 边界、可观测阶段边界。先算 oracle 每层专家并集在 16/64/256 token 窗口下的容量和传输需求，再比较 LRU/LFU、静态热门、阶段可观测预测、oracle。必须计入公共权重和 KV 占用，禁止只用 expert 容量当设备总内存。

第一关：若完美预知在可用内存内仍无法让足够多有用阶段不阻塞 WAN，则停止工作集下发路线；无须先训练 predictor。若 oracle 可行再检查在线预测的可达性。真实端云执行时间、能耗和质量必须另行实测。
