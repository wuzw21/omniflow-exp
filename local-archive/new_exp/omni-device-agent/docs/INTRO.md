# 研究定位与 Intro 草稿

定位：端侧持续视觉助手的推理部署。下文是研究动机稿，不包含尚未实现的方法或贡献声明。

持续视觉助手需要在用户提问之前积累证据。用户问“刚才第一件商品的型号是什么”时，相应文字可能已经离开画面；只在问题到来后启动视觉模型无法补回这一信息。对本地连续视频，一种可行做法是持续保留少量有用画面，再在问题到来时交给视觉语言模型。这里需要部署的是两个不同节奏的过程：一直发生的记忆维护，以及由用户触发的问答。

SVMemAgent 已给出这一过程的具体方法：在不知道未来画面、视频总时长和用户问题的情况下，在线决定丢弃新帧还是替换一个记忆槽，再使用保留帧回答问题。这提供了可以直接复现的基线；我们的工作不应把“未知问题下维护有限视觉记忆”重新命名为新任务。[SVMemAgent](https://arxiv.org/html/2609.18540v1)

有限记忆容量约束的是保留什么，并不直接回答这套方法在端侧能否持续运行。记忆写入需要处理到来的画面，问答需要加载或保持回答模型、读取记忆并生成输出。前者的成本随观察时长累计，后者决定用户等待。设备上的实际结果还取决于模型与状态是否常驻、后端支持和真实输入频率；不能从帧数上限或服务器逐帧延迟推导整机内存、响应时间和续航。

因此，我们先研究一个可测量的问题：在给定设备与回答质量要求下，原始在线记忆方法的持续维护成本和查询成本分别是多少？以作者代码、模型与设置为起点，先建立实际端侧执行和成本分解，再判断是否需要优化记忆写入、问答执行或二者之间的部署边界。当前不预设事件检测、记忆与模型唤醒必须联合，也不预设 KV 缓存是瓶颈。

尚未有实验支持“持续维护主导功耗”“模型唤醒主导延迟”或某种新调度策略。完成原版复现后再用证据替换这些待检验问题，而不是提前写出系统贡献。
