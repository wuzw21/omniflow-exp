## 证据与执行

- `docs/HANDOFF.md` 是当前入口；`experiments/legacy` 是冻结历史。旧 README、计划里的“正在运行/下一步”不能直接执行，先看最终结果和当前进程。
- 不修改归档文件。新实验使用 `runs/<新名称>/`，记录上游 commit、模型 revision、数据 hash、设备、依赖、命令、随机种子、原始输出和失败。不得覆盖旧结果。
- 区分论文报告、源码检查、解析估计、公开轨迹回放、实际算子执行与闭环任务。OCR 证据召回不是 QA 准确率；缓存命中计数不是延迟；单次正确回答不是任务成功率；末端内存不是峰值。
- 每次需求、故障和验收条件落实到项目既有可执行回归。明确未实现、未运行、失败和待真机验证；报告和模拟不能代替执行。不复制凭据、无关私人对话和用户原始敏感轨迹。
- 所有 bug 修复需真机验收，记录设备、版本、实际操作、结果及相关重启/恢复/重复操作。单元测试、模拟器、构建和源码检查只能补充。无设备时继续可执行工作，标注“待真机验证”。
- 上下文压缩优先复用受维护的官方/开源实现，核对接口、许可证、模型/协议、环境、持久化语义，最小集成。不能借“参考官方”自研替代，也不能引入第二套 agent loop、ACP 生命周期或历史来源；无法复用先说明兼容障碍。
- 如涉及 OmniFlow transfer，只使用 `~/Projects/Omni/OmniTransfer` 的真实实现；映射失败必须报告以触发 VLM fallback，不能回放源设备坐标或用简单查找替代。

## 科研写作

沿“问题→必要设置→实际证据→允许的结论”组织。降低 reader cost；一段只推进一个判断。图必须来自真实数据或明确公式，渲染后检查数值与可读性。区分观察、解释、假设；不把作者声称等同于已隔离验证的机制。充分比较超参数与强基线，不按金答案挑配置后冒充在线策略。不虚构贡献、放大微小收益或把负结果包装成突破。交付前做三轮编辑：事实/限定、推理顺序、冗余与措辞。尊重用户已确定的方向，不靠润色改变科学判断。
