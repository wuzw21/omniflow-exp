## 一、本次确定的三个结论（可直接引用，但注意条件）

**1. 之前报的"不稳定"被高估了，而且原因是配置不是模型。**

扫全部 293 份 RunLog：omniflow 共 199 次尝试，159 进 `current/`，40 进 `.archive/`。
但那 40 条里 **28 条其实是成功**（只是输给同等 golden 结果），真实失败 12 条，其中
**8 条是同一个原因** `vlm_planner_failed:Request timed out.`。

更关键的限制：这 8 条失败**全部来自 `SystemBluetoothTurnOn` 一个任务**，而它是唯一被反复
重跑的任务。所以 "5.7% 失败率" 是单任务的重复重试产物，**不能当作跨任务失败率引用**。

**2. 三个互相矛盾的计时缺陷（已修）。**

| 缺陷 | 后果 |
|---|---|
| `planner.py` 把请求硬顶到 `min(timeout, 30)` | CLI 的 60s 默认从未生效 |
| `engine.py` 用 `ExecutionControl()` 自己的 600s 默认构造 | 协议 deadline 写多少都没用，kernel 一律 600s 封顶 |
| `control.py` 拒绝任何 >600s 的 deadline | 抬 deadline 会直接抛错 |
| `planner_error_retries` 默认 0，无调用方设过非 0 | 一次网络抖动终结整个 episode |

**3. 已有 137 次完成 episode 的实测耗时是 10.1–232.4 秒（中位 53.3 秒），没有一次触及旧的
600 秒上限。** 所以 deadline 抬到 1200s **不会改变任何已记录结果**。这条是能写进论文的，
它证明改动是安全的而非调参。

## 三、MobiMem 对照实验的结论与边界

完整记录见 `docs/experiments/MOBIMEM_REUSE_20261106.md`。

同一分母（155 条运行、1004 个执行步）：

| 设计 | 复用率 |
|---|---|
| ActTree（同任务池） | 0.197 |
| ActChain（同任务池） | 0.433 |
| ActTree（跨任务池，中位 10 个历史任务） | 0.214 |
| ActChain（跨任务池） | 0.468 |
| **Function（本方法）** | **0.576** |
| Function + Transfer 证据 | 0.369 |

按任务等权复核结论不变（ActChain 跨任务 0.500 / 同任务 0.464）；短任务（≤3 步）占 18.1%
条数但只占 7.8% 步数，未污染结论。

**三个必须随身带的限制**：

1. **覆盖率不是成功率。** 155/155 全部通过 validator，因为 `current/` 只留成功。
2. **失败侧对照跑过了，但不成立。** 失败侧覆盖率 0.370 vs 成功侧 0.576，方向对，但脚本
   自己给出 `control_is_conclusive: false`：只有 8 条有执行步的失败（另 6 条一步未走），
   且 8 条全是同一个任务。**现在不能写"覆盖率导致成功"。**
3. **跨任务池不低反高**（0.468 > 0.433），说明回放类方法的复用率可以靠扩池刷高，与记忆
   原语好坏无关。所以论文里报 Function+Transfer 的 0.369，不只报覆盖率。

**论文能用什么**：只能写关系，不能写数字。正文可写"同等条件下 Function 覆盖的执行步多于
两种回放结构，且差距来自覆盖范围而非复用精度"；具体数字进附录且必须带轨迹数、分母定义、
池构造方式。不能写覆盖率→成功率的因果，不能与 MobiMem 的 37.5/59.7/77.3 并排或做减法。

## 四、修掉的真 bug（都在 HEAD 里就有，与本次改动无关）

**`DEFAULT_DEVICE` 不可用**：`protocol.py` 把默认设备拼成 `label:serial:port`，但启动器
`--device` 只接受标签。后果是**任何不带 `--device` 的实验在第一个任务之前就死**：

```
ValueError: unknown_configured_device:standard45562:emulator-45562:45562
```

根因是两个入口语法不同却共用一个常量（`run_tasks` 要标签，`run_task` 要
`LABEL:SERIAL:PORT`）。已拆成 `DEFAULT_DEVICE_LABEL` 与 `DEFAULT_DEVICE`，加了回归测试，
并**把 bug 临时放回去验证过测试确实会红**（3 个失败）。

过程中我自己引入又修掉的：`execution_timeout_seconds` 校验写成 `type(...) is float`
（测试传 int 就炸）；编辑器把 `import shutil` 与 `import subprocess` 粘成一行。
